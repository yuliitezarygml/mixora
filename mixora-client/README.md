# Mixora Client

Клиент Mixora на JavaScript, React, Vite и Electron. Соседний `../beckend` содержит Go app-layer API и готовый музыкальный движок. App-layer, PostgreSQL, Redis и development-почта запускаются из корневого `compose.yaml`.

## Запуск

```sh
cd /path/to/mixora
docker compose up --build -d

cd mixora-client
npm ci
npm run dev
```

Клиент: http://127.0.0.1:5174. Vite проксирует `/api` и WebSocket на `127.0.0.1:8080`. Mailpit для писем подтверждения и сброса пароля: http://127.0.0.1:8025.

SoundCloud и Spotify Client ID для обычного локального запуска не требуются: provider-клиенты движка инициализируются автоматически. Параметры app-layer и development-значения описаны в корневом `.env.example`.

```sh
npm run build
npm run desktop
npm run desktop:pack
```

Electron использует сборку `dist`, проксирует HTTP/WebSocket в тот же локальный Go API на порту 8080 и не запускает backend сам. `desktop:pack` собирает неподписанное приложение `release/mac-arm64/Mixora.app` для Apple Silicon. Подписанный установщик, notarization и auto-update пока не готовы. Origin фиксирован: `127.0.0.1:5174`; занятый посторонним сервером порт вызывает явную ошибку, а не потерю cookie/storage на случайном порту.

## Структура

- `src/components` — меню, плеер, карточки, модальные окна, исходная анимация волны.
- `src/pages` — главная, поиск, коллекция, детали, тематические разделы, настройки.
- `src/state/AppContext.jsx` — совместимый фасад сессии, плеера, очереди,
  Wave и настроек; durable library/event/preferences/history/playlists state
  вынесен в узкие модули `src/state/`. `usePlaybackSync` управляет WebSocket,
  `usePlayerPersistence` сохраняет account-scoped очередь и позицию.
- `src/lib` — HTTP-клиент, нормализация треков, маршруты и операции с коллекцией.
- `public/_next/static/css` — неизменённые таблицы стилей исходного клиента.
- `public/styles/fonts.css`, `public/fonts`, `public/assets` — оригинальные шрифты, SVG и медиа.
- `src/styles/integration.css` — привязка исходной разметки и дизайн-токенов к React.
- `desktop` — оболочка Electron без доступа страницы к Node.js.
- `docs/reference-styles.json` — исходные пути и SHA-256 всех перенесённых таблиц стилей.

## Что подключено

Вход, регистрация, HttpOnly cookie-сессии, подтверждение email и сброс пароля работают через Go app-layer API. Для вошедшего пользователя избранное, личные плейлисты, подписки и история хранятся в PostgreSQL и кэшируются локально; при первом входе существующая локальная библиотека этого аккаунта переносится на сервер, если там ещё нет данных. Гостевая библиотека остаётся на текущем устройстве.

Поиск и воспроизведение подключены через один source-aware adapter: SoundCloud, YouTube, VK, Bandcamp и Spotify preview. VK/Bandcamp сейчас принимают URL трека; Spotify отдаёт только доступный preview, не полное аудио. Временные media URL не сохраняются в библиотеку: клиент хранит устойчивую страницу источника и повторно разрешает поток через backend.

Плеер поддерживает паузу, full-width перемотку, громкость, очередь (перестановка и удаление будущих треков), повтор, перемешивание, like/dislike, меню трека и настройки звука. App-layer принимает события прослушивания, собирает «Мою волну» и синхронизирует состояние плеера между активными сессиями через WebSocket. После открытия очередь и позиция восстанавливаются на паузе; очереди разных аккаунтов изолированы.

На главной и в коллекции есть аккаунтные рекомендуемые плейлисты «Для вас», «Открытия» и «Для работы». Они используют существующий `/wave`, пересчитываются после изменения лайков, дизлайков, истории, поисков и языковых/explicit-настроек. Недавние найденные треки служат дополнительными seed, но не превращаются в вымышленные лайки. «Открытия» исключают знакомые треки. Подборку можно просмотреть, включить и сохранить отдельным снимком в личные плейлисты; сохранённый плейлист не меняется при следующем пересчёте. Источники сохраняются, Spotify явно помечен как фрагмент. Debounce и отмена запросов защищают от лишних пересчётов и запоздавших ответов другого аккаунта.

Рабочий `.env` включает локальную EmbeddingGemma через Ollama. Для полного Docker-профиля используйте `make embeddings`; `make recommendations` намеренно запускает облегчённый режим без embeddings. Наличие модели не означает, что каждый результат нейросетевой: UI показывает фактический режим ответа. При малом подходящем каталоге подборки могут пересекаться, и для rule-only «Для работы» это обозначено явно. Audio embeddings и измеренная оценка качества остаются следующими этапами.

Начальная подборка `src/data/catalog.json` содержит публичные метаданные SoundCloud. Аудио и ключи API в клиент не встраиваются. Актуальные результаты поиска и ссылки на воспроизведение запрашиваются через backend. Доступность конкретного трека определяется источником.

## Перенос интерфейса

Все 43 исходные таблицы стилей перенесены без изменения байтов и подключены в порядке исходного `index.html`; дополнительные таблицы маршрутов загружаются после них. Сохранены оригинальные цвета, шрифты, иконки, радиусы и брейкпоинты. Каркас, навигация, плеер, фон «Моей волны», вкладки и заголовки используют исходные CSS-классы. Название приложения — Mixora.

Обзор `/collection` восстановлен по исходному экспорту и пользовательскому скриншоту от 2026-10-08: заголовок 32 px с подписью, оригинальная обложка-сердце и реальное число любимых треков, список в две колонки и круглые исполнители. На узком экране список становится одноколоночным; пустое избранное ведёт в поиск. Рекомендуемые плейлисты расположены ниже исполнителей. Компонент находится в `src/pages/CollectionOverview.jsx`. Содержимое берётся из библиотеки Mixora, а не подставляется из скриншота; серверные подборки оригинала недоступны.

Размеры карточек коллекции ограничены 180 px на desktop и 148 px на mobile: длинное имя исполнителя или плейлиста обрезается и не растягивает обложку и страницу.

Карточки рекомендаций ограничены 220 px на desktop и 160 px на mobile. Их обложки используют локальные изображения Mixora и не зависят от доступности artwork первого трека. Ошибка внешней обложки в общей компоненте `Cover` показывает видимую иконку вместо пустой области. Последний visual QA и ограничения проверки записаны в `../design-qa.md`.

Плеер поддерживает текущие AAC HLS-адреса SoundCloud (`hls_aac_160_url`, запасной `hls_aac_96_url`) на `playback.media-streaming.soundcloud.cloud`, а также прежние HLS-адреса `sndcdn.com`. OAuth остаётся на сервере. Повторное нажатие после ошибки заново получает временную ссылку. Переход SoundCloud описан в [официальном объявлении](https://github.com/soundcloud/api/issues/441).

Все пути из экспорта исходного клиента перечислены в `src/data/original-routes.json` и распределены между страницами React. Это **не означает наличие всех сервисных функций**: клипы, концерты, тексты, подкасты, офлайн-загрузка и рекомендации Яндекса не подключены. Для них есть навигация и явные пустые состояния. Данные SoundCloud, экран входа Mixora и наполнение подборок отличаются от оригинала. Полное совпадение всех экранов по пикселям не подтверждено: исходная сборка при запуске показывает экран входа Яндекса, а исходных React-компонентов в экспорте нет.

Проверки:

```sh
npm test
npm run styles:verify
npm run format:check
npm run build
```

`styles:verify` сравнивает SHA-256 стилей и проверяет наличие используемых оригинальных классов. `styles:migrate` повторно копирует стили из соседнего исходного клиента и обновляет манифест. Оригинальная папка при этом не изменяется.
